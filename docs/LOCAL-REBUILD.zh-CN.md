# SLAM Toolbox 局部重建

对已保存地图选择矩形区域，创建新的原生地图分支，清理该区域相关历史扫描，再从保留观测的区域定位并进入选区重建。原地图保留，可继续加载或用于回退。本功能仅作用于 slam_toolbox。

## 使用

1. 在 Maps 中选择一个可加载的 slam_toolbox 地图，点击 **Local rebuild**。
2. 拖出需要重新测绘的区域，填写新地图名称，点击“创建局部重建分支”。
3. 将机器人放在选区外、清理后仍有有效观测的已知自由区域；确认后点击“在新分支开始增量建图”。
4. 等待初始化通过。存在候选点时，在地图服务主界面选择正确候选点。
5. 遥控或通过导航航点进入选区巡检，再保存为新的地图名称。无需依赖寻找未知区域的 Explore 策略。

创建分支后尚未启动运动。定位完成后由用户或导航任务控制机器人进入选区。地图保存沿用完整原生图和自动检查点机制。

## API

`POST /api/mapping/local_update`，Content-Type 为 application/json：

```json
{"base_map_id":"office-base","map_id":"office-room-update","bounds":[-1.28,-0.53,1.47,2.47]}
```

坐标使用已保存地图的 map 坐标系，单位为米，顺序为 xmin、ymin、xmax、ymax。返回新地图 ID、选区、原始图指纹、修改扫描数量、原生双文件校验状态和图统计。

启动沿用 `POST /api/mapping/start`：

```json
{"base_map_id":"office-room-update"}
```

局部准备接口和界面属于地图服务 Web API；没有修改共享 Robonix IDL，也没有改变 RTAB-Map 的建图、定位或持久化调用路径。

## 内部处理

- 遍历所有历史扫描，使用激光传感器位置及有效射线与选区求交。也处理节点在框外、射线进入选区的情况。
- 相交的整条历史射线设为 NaN，刷新点云、包围盒等缓存。保留所有节点、节点位姿、扫描 ID 和历史约束。
- 清理范围额外扩展一个地图栅格，以处理边界端点的栅格量化。
- Mapper 和 Dataset 的原生档案是独立加载的对象，须按扫描 ID 同步修改两套距离数据；分别保存 `.posegraph` 和 `.data`。
- 在独立进程中重载双文件，逐射线验证有效距离及 NaN 掩码一致，再冷加载生成占据图。新分支的节点、位姿、边数量必须与原图一致，图必须连通。
- 暂存目录、源图 SHA256 校验、写入同步及原子发布避免不完整分支进入地图列表；已有地图不覆盖。
- 初始化时拒绝选区内或未知/占据位置的起点，再沿用三帧实时扫描验证、里程计时间对齐和图交接检查。
- 完成后保存 `local-update-history.json` 记录来源及选区；该历史文件不会把已经重建好的区域永久标为禁止初始化的区域。

本版采用整条射线失效策略。尚未实现“保留选区之前的自由空间、在第一次交点处以无障碍终点截断”的精细策略，因此清理阶段可能使框外部分已知区域变成未知。新观测可重新补充这些信息。

## scene_207 实验（2026-11-10）

Ranger Mini + Piper，真实 MuJoCo `scenesmith_office_207` 场景。使用现有转换资源：保留纹理模型，每个静态家具使用一个碰撞包围盒。里程计为该仿真的理想里程计。

- 基线先运行真实 Robonix Explore，300 秒上限，实际约 302.5 秒超时结束，再经 Nav2 返回办公室补充观测。保存原图 289 节点、507 边、一个连通分量。
- 选取 `office5_side_chair_0`，在机器人静止时将实际可视及碰撞家具移到地面以下；66 条激光射线变化超过 10 cm，相机前后画面确认椅子移除。机器人位移约 0.107 mm。
- 普通增量对照保留原扫描，导航到椅子原位置在本次 120 秒目标预算内超时；目标足迹内原有的 13 个占据格仍在。
- 小选区分支作废 3227 条历史射线，涉及 56 帧扫描，不删除节点或边。相同五航点路线约 46.3 秒全部成功。椅子评估足迹 169 个格子全部恢复自由，原占据格残留为零。
- 重启整个 Robonix 服务栈、保持家具移除的仿真世界不变，再次巡检全部成功，旧障碍没有重现，旧节点的 NaN 掩码保持一致。
- 整屋选区作废 17104 条历史射线，涉及 92 帧，16 帧失去全部有效射线。先由 Nav2 导航至保留的走廊，再重新定位进入房间，五航点约 56.4 秒全部成功。旧房间已知区域恢复率 100%，房间外已知变未知仅一格（0.0025 m²）。
- 对清理后空房间内的启动请求进行实测，正确拒绝；对已重建地图则可正常初始化并继续导航。

以上为单一办公室、单个家具、两种选区范围的真实仿真闭环证据，不等同于实机或任意结构变化的验证。普通增量对照结果受该路线和预算约束，不表示普通增量在所有场景均无法更新。

## 检查与限制

原生 CTest 包含边界栅格及双文件持久化检查；后者还会故意换回未编辑 Dataset，确认校验会拒绝不一致档案。Python 回归覆盖输入校验、失败清理、原图不覆盖、RTAB-Map 拒绝及保留区域初始化。

暂不支持多边形选区，或带独立栅格编辑版本的源图；界面会拒绝后者以避免丢失用户编辑。历史约束被保留，并未自动判断其是否因原图错误而失效。大规模节点裁剪、长期反复更新的计算及存储增长、真实里程计误差和实机验证仍需后续工作。

构建沿用 `rbnx build -p <地图包路径>`，新增工具随原有图工具一起编译，不需要自定义 slam_toolbox 分支。

## 本次稳定性收尾

- 修复增量交接首帧只发送一次的问题：等待扫描订阅者与位姿发布者发现完成，再发送原始锚定扫描；没有确认时以 250 ms 间隔重发同一帧和相同时间戳，不重新设置初始位置。
- 真实 DDS 回归故意延迟订阅，并丢弃第一次位姿确认，第二次同帧交接成功；原有扫描倾斜过滤、延迟 TF、时间戳保持及恢复行为仍通过。
- 五轮完整 Robonix 重启分别约 30.8、29.6、29.2、28.7、32.7 秒完成初始化。辅助 `ros2 param` CLI 在部分轮次有发现缓存问题，未用该 CLI 判断建图成功；五轮均由真实服务状态、初始检查点及启动完成日志确认，日志中未出现首帧超时。
- 五轮后再次执行相同五航点，约 46.35 秒全部成功，保存 `office207-final-verified`：417 节点、708 边、一个连通分量。
- 独立重载最终地图、整屋重建地图和手动检查点，原始 289 个节点仍在，17104 个失效射线索引全部保持；旧节点在选区内的有效命中端点数为零。原图双文件 SHA256 未改变。
- 完整 Python 回归为 266 通过、2 个上游已有失败；干净上游版本也复现相同两项失败，分别为 candidate manifest 引用检查、RTAB-Map Docker 挂载测试。原生 CTest 2/2 通过。实际浏览器拖框、创建新分支和确认前禁用启动的测试通过。
- 一次手动检查点原生捕获约 72.8 ms、总耗时约 206.0 ms；仅为单次实测，不是无阻塞或高分位性能保证。
